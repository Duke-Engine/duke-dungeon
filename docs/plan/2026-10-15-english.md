# English, beside Uzbek

For the Steam audience. **Uzbek stays the default** (the owner's rule: Uzbek first); English is an overlay chosen at
launch. Switching is on the Settings screen (row *Til* / *Language*) and is spoken from the next launch, because the
data files are read once, in one language.

## Where the words live (the survey)

Everything a player reads is already data; almost none of it is in Java.

| What | Where |
|---|---|
| Front menu, credits roll's headings, the 65 fixed words of the engine's menus (`Words`), splash and load hints | `data/world/menu.duke` (`MainMenu`, `Splash`) |
| HUD, tooltips, skill card, hero panel, choose-hero/mode/stage questions | `data/world/hud.duke` (`Hud`) |
| Party (host / join), saves and load/save screens | `data/world/party.duke`, `saves.duke` |
| Hero sheet, quest log, map, tracker, place names on the map (`Places`) | `data/world/screens.duke` |
| Controls row, tower travel | `data/world/controls.duke`, `travel.duke` |
| Mission lines, floating words, worn places, attribute words, key hints, a few items | `data/world/world.duke` |
| Items: bases, prefixes, uniques and their lore, potions, rarities, name parts, card words | `data/world/loot.duke` (`ItemRules`, `ItemBase`, `Affix`, `Unique`, `Potion`) |
| Food, campfire words, the meal skill | `data/world/food.duke` |
| Units' `DisplayName`, heroes' `Title`, **skills' `Name` and `Blurb`**, passives | `data/units/*.duke` |
| Props' names and the gate's lines | `data/props/*.duke` |
| People (`Speaker`, `Npc` role), every dialogue `Text`, quests (`Title`, `Description`, objectives), title cards, campaign names and blurbs, the medallion's words, the merchant and trade words, credits headings | `data/story/*.duke` |
| Stage list (title, description of each map) | `maps/*/*.map` heads, read in `Stages` |
| Engine strings (pause menu, settings, the keys list) | `Words` in `menu.duke` -> `Shell.word`; the engine's own English is the key |
| Fallbacks written in Java (`ItemRules.DEFAULTS`, `Trade.DEFAULTS`, `Dialogue.DEFAULTS`) | every field is set by data, so they are never shown; left alone |

Not text, and left alone on purpose: ids (`Name = Act1Queen`, `Map = poytaxt`, `Zone = ...`, `Target = ...`), sound
and model paths, `sounds/`, `projectiles/`, `animations/` (written in English already), `CREDITS.md` (English).

## The mechanism: texts by key, a table a language, applied where the files are read

Reworked 2026-10-21 (the owner's design): the table was keyed by the Uzbek itself; it is now keyed by **where a text
lives**, so the same Uzbek word can mean two things in two places and a changed Uzbek line is seen as changed.

* **Uzbek is not a table.** The data's own words are the source and the default; a key a table lacks is said in Uzbek.
* **A key** is `<BlockType>.<BlockName>.<Field>`: the block opened at the left margin (`Conversation`, `Quest`, `Hud`),
  its own `Name =` two spaces in (a block without one is just its type: `MainMenu.Subtitle`), and the field (or list)
  the text stands under, however deep. The 2nd, 3rd... text under the same field of that block is `.1`, `.2`...: the
  three line texts of `Conversation BattleHolds` are `Conversation.BattleHolds.Text`, `.Text.1`, `.Text.2`; a list's
  items likewise (`MainMenu.Words.12`). So moving a line within its block renumbers its neighbours' keys (the checker
  then shows them stale).
* **Collisions.** A key two files would both derive is written, for every file deriving it, with the file before it:
  `story/act1:Quest.Training.Title` (the path under `data/`, or `maps/<map>/<file>` for a map folder's `.duke`, without
  `.duke`; the path rather than the stem, because `story/act1` and `units/act1` share a stem). A key still said twice
  after that is refused by `Lang.places`, naming both places. None collide today. The game looks a place up by
  `<file>:<key>` first, then by `<key>`.
* **The code's own words** have keys of their own: `Map.<map>.Title` / `Map.<map>.Description` (the stage list, from
  the `maps/*/*.map` heads) and `Settings.Language` (the settings row; its Uzbek is in `Lang.CODE`). They are said with
  `Lang.t(key, uzbek)`.
* `src/main/resources/data/lang/<code>.duke`, one a language (`en.duke` today): `Language = English` first, then one
  row a line, `Key = "the English"  ; uz: the Uzbek it translates`, under a `; ---- data file ----` heading a file in
  the order the game reads them. A key a player reads that is not yet translated is a comment line
  `; Key = ""  ; uz: ...`. Not listed in `game.duke`: it is not a block file.
* `content/Lang.java`. `Content.read` (the one door every data file comes through) passes each `data/` file through
  `Lang.apply`, and `DungeonSettings` each map folder's `.duke` blocks. It rewrites **only places that hold text**: every
  quoted string, and the unquoted value of a field whose name says it is text (`DisplayName`, `Text`, `Title`, `Blurb`,
  `*Word`, `*Hint`, ...; the list is `Lang.TEXT_KEYS`), plus one-line lists of bare words (`Slots`, `WornSlots`,
  `Rarities`, `FirstNames`, `SecondNames`). A block's own `Name` (indent 2) is an id and never rewritten, a skill's
  nested `Name` is text; fields that hold ids (`Zone`, `Open`, `Where`, `Map`, `Route`, ... `Lang.ID_KEYS`) are never
  offered. Lines, comments and ids are not touched, so no record, binder or screen knows there are languages, and
  saves (which hold ids) load in any.
* The engine's `Words` rows (`"Resume = Davom etish"`) become `"Resume = Resume"`: English says what the client says when
  a game names none.
* Languages: Uzbek first, then every table in `data/lang` by file name (`Lang.CODES`, `Lang.NAMES` = `O'zbekcha`,
  then each table's `Language`). `--lang=en|uz` on the command line, else the setting `game.language` (an index:
  0 Uzbek, 1 English) kept by the Settings row `Main` adds (`Shell.settingsRow`, E79), else Uzbek. `Lang.use` is
  called first thing in `Main.main`.
* Fonts: the menu font (Cinzel, bitmap) has ASCII and a few dashes (`—`, `–`) and quotes `« »`; English uses nothing
  else (`LangTest.theEnglishFitsTheFont` fails on any other character, so write `...`, not an ellipsis, and `'`, not
  a curly quote). Uzbek needs only the ASCII apostrophe, which the game already uses. The 3D text uses the same fonts.
* The move (2026-10-21): `tools.LangTable --old=<table of before>` wrote the keyed table from the Uzbek-keyed one, the
  way the game read it (the file's `@data/...` row, then the field's `@Field` row, then the plain one), and a test
  proved every file read in English exactly as before (commit c0c7ef3); the old table was then removed. A branch that
  still edits the old table can be moved the same way: `./gradlew langTable --args="en --old=<its old en.duke>"`.

## The checker

`LangTest` (and `./gradlew langReport`, which prints the same per language without failing): every row's key is a
place in the data (no **unused** keys); every row's `; uz:` is the data's Uzbek at that key (else it is **stale**: the
Uzbek changed and the English was not looked at; the failure names the key and both texts); `%d`/`%s`/`{name}` the
same in both; English the font can draw; the menus, the HUD, the screens, saves, party, controls, travel,
`world.duke` and the stage list (`LangTest.CORE`) whole. Every other key English lacks is **missing**: a warning,
listed per file in `build/lang-missing.txt`.

## How to add a translation

1. `./gradlew langReport` (or the test) lists what each table lacks, by file, with the Uzbek.
2. In `data/lang/en.duke`, under the file's heading, take the `; ` off the key's comment line and write the English:
   `Quest.Training.Description = "..."  ; uz: <keep as it is>`. A name that is the same in both (a person, a village,
   a licence line) is a row whose English is its Uzbek: it says "looked at".
3. New lines a branch adds have no comment line yet: `./gradlew langTable --args="en"` writes the table again from
   the data, every row kept by key, new keys as comment lines, keys the data lost dropped (notes added by hand are
   not kept). A stale row keeps its old `; uz:`: fix its English, then copy the new Uzbek into it.
4. Rules the test enforces: the same `%d`/`%s`/`{name}` placeholders on both sides; characters the font can draw; a
   `Unique`'s lore and names may not contain `,` or `|` (DungeonSettings refuses them).
5. Style: fantasy tone, short. People and places keep their names (Erika, Laylo, Karim, Olmazor); titles are translated
   (*Qo'mondon* Commander, *Malika* Queen, *Temirchi* Blacksmith, *Oqsoqol* Elder); *Yalmog'iz kampir* is Baba Yaga.
6. Try it: `./gradlew run --args="--lang=en"`.

## How to add a language

`./gradlew langTable --args="de --language=Deutsch"` writes `data/lang/de.duke` with every key as a comment line; it is
offered on the Settings row from then on (index 2 by file name order, `--lang=de`). Translate rows as above. The
checker's tests name `en`; give a new table the same checks when it is to ship (the font, too, if it needs letters
past ASCII).

## What is not translated

* Anything a branch adds after this one, until its row is written (see above).
* The baked-in text of art (none known), and the voice lines (none are speech).
* The engine, where it says a word of its own that no `Words` row names (it says them in English already).
* Save slot files written by an older build are read as before; they hold ids, not words.
